# TE_OBSERVER — Ordinative Observation System

**Canonical file:** `FRAMEWORKS/TE_OBSERVER_v1_1_EN.md` · version 1.1 · load order 8 · on demand, when integration across modules or a trajectory projection is required · prerequisites: SVP; integrates LENS, PPRO, SCIMS, VERI.

## In one paragraph

OBSERVER is the integrated system: it sees what a system does to those who participate in it, where it came from, where it is going, and what ordinative elements can be recovered from it. It combines four strata (source, evolution, function, carriers) with two temporal modes, historical (a concluded arc: purpose, effects, lessons) and current (an ongoing trajectory: the three-course model, divergence analysis, a Lyapunov reading of stability, attractor identification, alternative trajectories, correction scenarios and their viability, a therapeutic evaluation). Version 1.1 added confidence grading to the three courses, a mandatory disconfirmant-processing checkpoint before every conclusion, and an anti-narrative-drift protocol for multi-output sessions. The module also makes the AI proactive (it proposes subjects and asks confirmation), extractive (it recovers ordinative elements from degraded systems) and generative (it proposes new frameworks, extensions and corrections in fixed formats).

## When it applies

Complex integrated analysis; trajectories and projection; Lyapunov stability; correction viability; any subject with a source, a transmission, participants and effects (`§2.1`): individuals, organisations, institutions, political and religious entities, nations, ideologies, technologies, economic systems, movements, and new categories the AI is asked to propose (`§2.1.2`). The original modules stay available for direct use when OBSERVER mode is not required (`§1.4`).

## Before you start

SVP. Choose the mode: historical for a concluded trajectory (complete data, no projection uncertainty), current for an ongoing one (`§2.2`). Expect the model to propose and to ask for confirmation before proceeding (`§7.2`), unless you have given an explicit instruction.

## The procedure

1. **Observation framework** (`§3`), integral before label: Stratum S source (S0 source singularity: verified, probable, constructed, absent; S1 transmission proximity; S2 structure vs image construction; S3 certification mechanism: mythological, testimonial, institutional, empirical, absent); Stratum E evolution (E0 evolutionary position of the source with the bifurcation protocol; E1 transmitters at, above or below source level; E2 identity vs engramma expression; E3 truth/power as vector or instrument; E4 degeneration probability with its factors; E5 generative capacity: singularities, variations, copies, dependents); Stratum F function (F1–F8, as in VERI); Module P carriers (P1–P8, as in VERI).
2. **Historical mode** (`§4.1`): arc reconstruction (origin, phases, conclusion), purpose analysis (declared vs emerged, read through SHACK/STEER/ERES), effects verification (participants, environment, at distance, unintended), lesson extraction.
3. **Current mode** (`§4.2`): the three courses, initial, declared, actual, each element graded; divergence analysis (initial ≠ declared: drift, medium; declared ≠ actual: deception or self-deception, high; initial ≠ actual: complete deviation, critical); the Lyapunov framework: stability on five dimensions (internal coherence, external adaptation, leadership, resources, narrative) into a composite index Λ, attractor identification, alternative trajectory evaluation, correction scenario projection; therapeutic evaluation, ending in a declared correctability (Controfase applicable, or non-applicability with the reason).
4. **Mandatory disconfirmant processing** (`§4.2.5`) before writing any conclusion: state it, list the contradicting data, test whether it weakens, invalidates, qualifies or leaves the conclusion (with a structural explanation), write with the processing visible; "despite [data], the conclusion remains" more than twice triggers P-AI.
5. **Anti-narrative-drift** (`§4.2.6`) in multi-output sessions: re-anchor (which prior elements are S₀ vs S₂–S₃), independence check, drift detection (confidence rising without data), narrative vs structural coherence, the fresh-eyes test; a recalibration note after drift in three or more outputs.
6. **Ordinative extraction** (`§5`): layer analysis, identification of ordinative elements, recovery assessment, transplant viability, and the criteria for non-recoverability.
7. **Framework integration** (`§6`): autonomous selection (individual → LENS; control patterns → PPRO; threshold impact → SCIMS; participant impact → VERI; everything → full OBSERVER), with the combinations by subject type.
8. **AI operative protocol** (`§7`): proactive identification and the `[SUBJECT PROPOSAL]` format, `[NEW CATEGORY PROPOSAL]`, confirmation before analysis, output delivery, documentation of framework choices, adaptations, limitations and anomalies.
9. **Evolution protocol** (`§8`): `[NEW FRAMEWORK PROPOSAL]`, extension and correction proposal formats, anomaly signalling; the route by which a domain not yet covered gets a module (`CONTRIBUTING.md`).

## The output

The templates of `§9`: historical analysis, current analysis (with the three courses, divergences, Lyapunov, attractor, correction scenarios, therapeutic evaluation, extraction), evolution proposal.

## Reading the output: checklist

- [ ] The three courses are separated and graded; the divergence class is named with its severity.
- [ ] Λ and the attractor are argued from the five dimensions and the evidence, not asserted; correction viability is stated as a fact, "neither false hope nor premature despair" (`§10.1`).
- [ ] Every conclusion shows its disconfirmant processing; in a multi-output session, the re-anchoring is visible.
- [ ] Extraction was attempted even in the worst case (`§10.1`, principle 5).
- [ ] The mode was chosen and respected; projection appears only in current mode.

## Pitfalls the document names (`§10.2`)

Reverence, demonization, antiquity = validity, complexity = depth, diffusion = validity, current = progress, scale = importance, narrative capture, confidence inflation, confirmation on request, attenuator, classification lock. And the one the 1.1 revision was written for: the module that invented "Zombie di classe S" rather than revise a classification (`§3.2`, E0 rationale).
